**Step A — Add useFriendsReading hook:**

Add `useFriendsReading` to `useSocial.ts`. Place it immediately after the `useFeed` function (in the SOCIAL-03 section).

The hook uses `useQuery` (not `useInfiniteQuery` — this is a fixed first-page fetch for a horizontal scroll row, not infinite scroll):

```typescript
export function useFriendsReading() {
  return useQuery({
    queryKey: QUERY_KEYS.friendsReading(),
    queryFn: () =>
      api
        .get<Page<FriendsReadingItem>>('/feed/friends-reading', {
          params: { page: 0, size: 10 },
        })
        .then((r) => r.data),
  });
}
```

Import `FriendsReadingItem` from `'../types/api.types'` — add it to the existing type import at the top of the file. Do not add a new import statement; add to the existing `import type { ... } from '../types/api.types'` line.

**Step B — Fix useFollowUser and useUnfollowUser onSuccess invalidation:**

The current `onSuccess` in both hooks does:
```typescript
queryClient.invalidateQueries({ queryKey: QUERY_KEYS.profile(userId) });
queryClient.invalidateQueries({ queryKey: QUERY_KEYS.feed() });
```

Replace BOTH `onSuccess` blocks (in `useFollowUser` AND `useUnfollowUser`) with:
```typescript
onSuccess: () => {
  // exact: false ensures all profile sub-pages (e.g. ['profile', userId, 0]) re-fetch
  // when follower/following counts change — DISC-03 fix
  queryClient.invalidateQueries({ queryKey: QUERY_KEYS.profile(userId), exact: false });
  queryClient.invalidateQueries({ queryKey: QUERY_KEYS.feed() });
  queryClient.invalidateQueries({ queryKey: QUERY_KEYS.friendsReading() });
},
```

The third invalidation (`QUERY_KEYS.friendsReading()`) ensures the "Friends are reading" section refreshes when the user adds or removes a friend.

Update the JSDoc on `useFollowUser` to note the DISC-03 fix and `exact: false` semantics.
