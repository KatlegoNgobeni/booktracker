    Step 6 — Switch to Want to Read tab: `page.getByRole('tab', { name: 'Want to Read' }).click()`. Wait for shelf entry: `expect(page.getByTestId('shelf-entry-card').first()).toBeVisible()`.

    Step 7 — Open the shelf entry editor: `page.getByTestId('shelf-entry-card').first().click()`. Wait for navigation to the edit page (URL contains `/edit` or `/shelf/`).

    Step 8 — Change status to Currently Reading: `page.getByLabel('Status').selectOption('CURRENTLY_READING')`. Set current page: `page.getByLabel('Current Page').fill('150')`. Click update: `page.getByRole('button', { name: 'Update Progress' }).click()`. Wait for button to re-enable (not in "Saving…" state): `expect(page.getByRole('button', { name: 'Update Progress' })).toBeEnabled()`.

    Step 9 — Mark as Read: `page.getByLabel('Status').selectOption('READ')`.

    Step 10 — Rate 5 stars: `page.getByRole('button', { name: 'Rate 5 stars' }).click()`.

    Step 11 — Write review: `page.getByLabel('Review').fill('An E2E test review.')`.

    Step 12 — Save: `page.getByRole('button', { name: 'Save Changes' }).click()`. Wait: `expect(page).toHaveURL('/shelf')`.

    Step 13 — Verify stats: `page.getByRole('link', { name: 'Stats' }).click()`. Wait: `expect(page).toHaveURL('/stats')`. Then: `expect(page.getByTestId('stat-books-all-time')).toContainText('1')` — the books-read-all-time counter must show 1 or higher.

    Single test: "User B sees no User A data after sign-in boundary"

    The test receives `{ browser }` from the fixture (Playwright passes `browser` automatically when the test function parameter destructures it). Type: `async ({ browser }: { browser: Browser })`.

    Implementation:

    Part 1 — User A adds a book:
    - `const ctxA = await browser.newContext({ storageState: AUTH_A })`
    - `const pageA = await ctxA.newPage()`
    - `await pageA.goto('/search')`
    - Fill searchbox with `'The Hobbit'`, press `Enter`
    - Wait for `getByTestId('book-search-results')` to be visible
    - Click first result link
    - Click `getByRole('button', { name: 'Want to Read' })`
    - Wait for `getByText('On shelf: Want to Read')` to be visible
    - `await ctxA.close()`

    Part 2 — User B sees empty shelf:
    - `const ctxB = await browser.newContext({ storageState: AUTH_B })`
    - `const pageB = await ctxB.newPage()`
    - `await pageB.goto('/shelf')`
    - `await expect(pageB.getByTestId('shelf-entry-card')).toHaveCount(0)` — User B's shelf must be empty
    - Additionally assert User A's book title is not visible: `await expect(pageB.getByText('The Hobbit')).toHaveCount(0)`
    - `await ctxB.close()`

    Note on the two-context approach (from RESEARCH.md Pattern 4): Each browser context has isolated storage, so switching from ctxA to ctxB is a true session boundary. This tests the API data isolation (each request uses User B's JWT) which is the critical property E2E-04 pins. The in-memory TanStack Query cache leak is separately tested by unit tests in `auth.test.ts`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User A context → User B context | Two browser contexts must not share any in-memory or storage state; each gets its own JWT |
| Browser → /api/shelf (User B) | Spring Boot must return only User B's shelf entries for User B's JWT; E2E-04 verifies this |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-16-07 | Elevation of Privilege | Cross-user data visibility (the property E2E-04 guards) | high | mitigate | auth-boundary.spec.ts asserts `toHaveCount(0)` for shelf-entry-card in User B's session. If this test fails, it means the API is leaking User A's data to User B's JWT — a critical security regression that must block the phase. |
| T-16-08 | Tampering | reading-loop.spec.ts modifies User A's shelf state; order dependency with auth-boundary.spec.ts | low | accept | Both tests use User A's auth. The reading-loop adds a book; the boundary test asserts User B sees zero entries. These are independent — User B's shelf is always empty regardless of User A's state. `workers: 1` (sequential execution) prevents race conditions. |
</threat_model>
