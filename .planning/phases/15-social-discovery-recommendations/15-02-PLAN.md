**Step A — Create FriendsReadingItemDto.java:**

Create `src/main/java/com/booktracker/social/FriendsReadingItemDto.java` as a Java record (same style as existing DTOs that use records in this codebase; if the codebase uses plain classes for DTOs, match that pattern by reading `FeedItemDto.java`):

Fields (all String, @JsonInclude NON_NULL on the class):
- `entryId` — user_books UUID as string
- `userId` — reader's UUID as string
- `displayName` — reader's display name
- `bookTitle` — book title
- `bookOlKey` — short-form work key (stripped of "/works/" prefix)
- `bookCoverId` — nullable
- `bookAuthors` — nullable, comma-joined

These seven fields match the `FriendsReadingItem` TypeScript interface that Plan 03 will add to `api.types.ts`.

Do NOT include `rating`, `review`, `dateFinished` — those fields are not applicable for CURRENTLY_READING entries.

Annotate the class/record with `@JsonInclude(JsonInclude.Include.NON_NULL)` to suppress null fields in JSON.
Package: `com.booktracker.social`.

**Step B — Add findFriendsCurrentlyReading to FriendRequestRepository:**

Append the following method to `FriendRequestRepository.java` (after the existing `findFeedForFriends` method). The query mirrors `findFeedForFriends` with three changes:
1. Filter `ub.shelfStatus = 'CURRENTLY_READING'` instead of `'READ'`
2. Remove the `ub.dateFinished IS NOT NULL` clause (no dateFinished for in-progress books)
3. Order by `ub.createdAt DESC` instead of `ub.dateFinished DESC`

Use string literals for the status value (`'CURRENTLY_READING'`) — NOT enum class references. This matches the existing `'READ'` and `'ACCEPTED'` string-literal style in all other JPQL queries in this file.

The `countQuery` MUST be included (Pitfall 1 from RESEARCH — Hibernate 6 cannot auto-derive count from JOIN FETCH). The countQuery omits JOIN FETCH and ORDER BY.

Method signature:
```
Page<UserBookEntity> findFriendsCurrentlyReading(@Param("userId") UUID userId, Pageable pageable);
```

Both the value query and countQuery must cover bidirectional friend lookup (OR condition with two IN subqueries on `fr.recipient.id` and `fr.requester.id`), exactly as `findFeedForFriends` does. Copy the bidirectional subquery structure verbatim, changing only the filter condition and ordering.
